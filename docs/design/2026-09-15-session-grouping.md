# 会话侧栏分组设计

> 本文已被 [Superpowers 正式设计评审稿](../superpowers/specs/2026-09-15-session-grouping-design.md) 替代，以下仅保留初稿记录，不作为实施依据。新稿修正了搜索范围，并以现有轮询方式替代此稿提出的摘要 SSE 扩展。

状态：设计提案，未接入产品。本文以用户最后确认的“仅用于分组，不共享信息”为边界。

## 1. 目标与范围

侧栏提供「置顶」「项目」「未分组会话」，帮助用户整理已有会话。项目只是可命名的会话分组，不对应代码目录，不共享文件、知识、指令、消息或记忆，不改变 Agent 执行和上下文装配。

首版包含项目创建、重命名、删除、折叠，会话置顶、取消置顶、移动到项目、移出项目，以及项目内新建会话。保持现有会话搜索、标题编辑、选中状态和执行状态展示。首版只提供一级项目，不引入嵌套分组、拖拽排序、项目置顶或归档能力。

## 2. 布局与交互

```text
Data Agent
  新会话
  搜索会话

置顶
  每周经营数据复盘                 …
    经营分析
  常用 SQL 与指标核对              …
    未分组

项目                              +
  ▾ 经营分析                      +
      分析 9 月销售额变化         …
      华东区域毛利率对比          …
  ▾ 用户增长                      +
      新用户留存分析              …
      渠道转化率下降原因          …
  ▸ 临时研究                      +

未分组会话
  解释这段查询语句                …
  查看昨日订单情况                …
```

- 延续当前暖灰底色、单行导航和轻量选中背景。侧栏建议宽度 280～320px；会话标题过长时省略，悬浮可查看完整标题。
- 项目行展示折叠箭头、文件夹图标、项目名；项目下会话缩进。点击项目名仅展开或收起，不打开新的项目工作台。
- 项目区「+」创建项目；项目行「+」在该项目中新建会话。全局「新会话」始终创建未分组会话，避免继承当前会话的分组产生歧义。
- 会话行「…」提供置顶/取消置顶、移动到项目、重命名。移动菜单包含「未分组」和全部项目。项目行更多菜单提供重命名、删除项目。
- 菜单可通过键盘访问；触屏保留明确入口。菜单操作不得触发打开会话；Esc 关闭菜单，关闭后恢复焦点。
- 无项目时保留创建入口；有项目但无未置顶会话时显示空状态。加载中、加载失败、真正为空分别呈现，避免失败时误显示空列表。

## 3. 归属、展示和排序规则

1. 一个会话只能属于一个项目，也可以没有项目。项目归属与置顶状态是独立属性。
2. 置顶会话只在置顶区展示一次，并显示所属项目名称。其项目归属保留，取消置顶回到原项目；无项目则回到未分组区。
3. 移动已置顶会话只改变项目归属，继续留在置顶区；当前打开的会话、消息和运行过程均保持不变。
4. 置顶区按置顶时间倒序，同时间按会话 ID 倒序稳定排序。项目按创建时间正序、项目 ID 正序排列，重命名和新消息不改变项目顺序。
5. 项目内及未分组区沿用现有会话更新时间倒序、会话 ID 倒序排序。置顶/移动属于元数据操作，可推进更新时间；首版接受因此产生的组内排序变化。
6. 若显示项目计数，计数表示当前项目树中可见的未置顶会话数量，避免显示总数却找不到被置顶的条目。
7. 搜索沿用会话标题匹配，覆盖全部会话；结果保留分区和项目路径。搜索时临时展开命中的项目，清空搜索恢复用户之前的折叠状态。
8. 删除项目只解除会话归属，会话、消息及执行记录保留；已置顶会话继续置顶。确认文案明确说明「项目内会话将移至未分组，置顶状态保留」。
9. 折叠状态保存在浏览器本地，使用服务实例和项目 ID 区分；归属和置顶状态持久化到服务端。

## 4. 当前实现与最小改动

当前 `ConversationList.tsx` 渲染平铺列表；`App.tsx` 负责会话加载、排序、搜索与选中。后端 `ConversationSession` 和 `ConversationSessionEntity` 尚无分组或置顶字段。

建议新增 `conversation_project` 表，复用持久化审计基类、ID 和时钟。字段包含项目业务 ID、名称、版本及既有通用审计字段。项目名去除首尾空白后为 1～60 个字符；首版允许同名，关联始终使用 ID。

会话表新增：

| 字段 | 语义 |
| --- | --- |
| `project_id` | 可空的项目业务 ID；空表示未分组 |
| `pinned_at` | 可空的置顶时间；空表示未置顶；重复置顶不刷新时间 |

不复用 `tag`，该字段已有检索、评测隔离和业务分类语义。历史会话的两个新字段默认为空，升级后全部进入未分组，原有消息和上下文不变。

- `agent-domain`：会话新增组织属性和轻量项目模型。
- `agent-persistence`：迁移、Entity、Mapper、ServiceImpl 和映射；使用 MyBatis-Plus 与现有 MapStruct，不为普通 CRUD 添加 XML SQL。表与字段均补中文数据库注释。
- `agent-web`：项目接口、会话组织操作、纯 View 组装、REST/SSE 契约测试。组织操作不查询消息历史或重建执行详情。
- `frontend`：侧栏按三类区域派生显示，复用会话行的标题编辑及状态展示；仅在需要时提取项目行和菜单组件。
- `agent-server`：仅补所需装配及集成验证；无需新增 Maven 模块。

## 5. 建议接口

以下为待实施的接口提案，不代表当前已提供的契约：

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/agent-projects` | 返回项目轻量列表，包括空项目 |
| `POST /api/v1/agent-projects` | 创建项目，输入 `name` |
| `PATCH /api/v1/agent-projects/{projectId}` | 重命名，输入 `name`、`expectedVersion` |
| `DELETE /api/v1/agent-projects/{projectId}?expectedVersion=...` | 删除项目并解除会话归属 |
| `PUT /api/v1/agent-sessions/{id}/organization` | 输入完整的 `projectId`（可空）、`pinned`、`expectedVersion`，返回轻量会话摘要 |

现有创建会话接口增加可选 `projectId`；现有会话列表、详情和前端模型增加 `projectId`、`pinnedAt`。原标题修改接口保持原职责。

组织接口为明确赋值，不提供“切换置顶”指令；重复请求不会反复切换状态。同一个会话的并发修改沿用版本检查，冲突返回 409，前端刷新元数据并保留用户目标供重试；不得静默覆盖较新的移动结果。

删除与移入必须协调：在持久化层锁定目标项目后校验其存在，项目删除也持有同一项目锁；事务内先解除会话关联，再删除项目。依赖数据库外键约束防止孤立关联，禁止级联删除会话。局部更新必须维护版本，避免运行中的会话旧快照覆盖组织字段。实施前应检查所有会话整行更新路径和锁顺序。

## 6. 同步与失败处理

当前摘要 SSE 仅包含会话 ID、执行状态和更新时间，无法同步项目名称或空项目变更。不能只改前端分组而忽略这一限制。

建议扩展现有摘要快照为完整的侧栏轻量快照：`projects` 携带项目列表，`sessions` 包含标题、归属、置顶时间、版本、状态及更新时间。指纹比较同时覆盖两个列表，复用现有快照收敛机制；不推送消息正文。实施时同步维护 Schema、示例和客户端解析器。

REST 操作成功后更新本地模型；新快照使其他标签页和重连客户端收敛。请求期间禁用同一对象的重复操作，失败保留原列表并展示重试入口。前端必须协调 REST 响应和 SSE 快照的先后顺序，避免旧快照短暂撤销已成功的操作；实施时使用版本比较并验证完整快照的增删处理。

## 7. 实施验收

- 创建项目后刷新仍存在；空项目可见；重命名后置顶会话的项目来源同步更新。
- 会话可在项目间及未分组间移动；每个会话在侧栏恰好出现一次。
- 置顶、取消置顶、移动已置顶会话均符合归属和排序规则。
- 删除含运行中会话的项目保留消息与执行，移入/删除并发不产生孤立关联。
- 新建会话正确使用显式项目；全局新建始终未分组；搜索和折叠状态符合规则。
- REST/SSE 重连、跨标签页更新、请求失败和版本冲突不会丢会话或错误重置分组。
- 回归标题编辑、会话选择、执行状态、消息流与现有上下文策略。

实施后先执行覆盖迁移、组织服务和契约的聚焦 Maven 测试，再按改动范围运行 `agent-server -am test`；前端执行相关 Vitest 测试与生产构建。当前交付仅含设计与效果稿，未修改 Java、数据库迁移或产品前端。
