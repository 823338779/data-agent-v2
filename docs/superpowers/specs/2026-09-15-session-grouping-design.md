# 会话侧栏分组设计

状态：用户已于 2026-09-15 确认设计；2026-09-16 完成实现与验证，记录见实施计划。

采用 Superpowers brainstorming 完整设计路径：本功能增加项目实体、公开接口及前端组织状态，属于跨层设计。本文是唯一设计正文，替代此前 `docs/design/2026-09-15-session-grouping.md` 草案；实际接口以同步更新的 `contracts/openapi.yaml` 为准。

## 1. 目标与边界

侧栏提供「置顶」「项目」「未分组会话」。项目仅用于整理会话，不共享文件、知识、指令、消息或记忆，不影响 Agent 执行及上下文装配。

首版提供：一级项目创建、重命名、删除、折叠；会话置顶、取消置顶、移入/移出项目；项目内新建会话。保留搜索、标题编辑、选中状态、运行状态及当前窄屏侧栏行为。

不增加项目工作台、项目路由、嵌套项目、多重归属、拖拽排序、项目置顶或归档。继续使用固定租户和固定身份，不设计成员或权限。

## 2. 方案比较与选择

| 方案 | 优点 | 代价与边界 |
| --- | --- | --- |
| 项目表 + 会话归属、置顶字段（推荐） | 支持空项目、持久保存和跨浏览器恢复，符合现有会话模型 | 增加迁移、项目操作接口及侧栏聚合查询 |
| 浏览器本地分组 | 无需改动后端 | 清理本地数据丢失分组，不能跨设备恢复 |
| 通用文件夹树 + 多对多关联 | 可支持嵌套和多重归属 | 引入当前不需要的树、排序及节点类型 |

选择第一种，复用既有模块、持久化框架和轮询，不引入新的长连接。

### 已核对的仓库事实

- `ConversationList.tsx` 当前为平铺导航，支持打开、双击改名和执行状态标识。
- `App.tsx` 搜索匹配标题和 `tag`；存在后台运行会话时，每 60 秒轮询摘要。
- 当前前端只订阅正在查看的运行中会话的详情 SSE，没有订阅后端 `/summary-events`。此前草案提出扩展摘要 SSE，本方案取消这一非必要改动。
- `ConversationSessionService` 已使用 MyBatis-Plus `ServiceImpl`、Lambda Wrapper 和 MapStruct。会话共享 `version` 还会因消息提交、活动记录等推进。
- `AuditedEntity` 提供审计字段和逻辑删除。项目删除沿用逻辑删除，不设计物理删除。
- `ConversationPersistenceMapper.updateEntity(...)` 负责会话模型映射；新组织字段必须明确隔离写入职责。
- 主 Flyway 迁移当前到 `V4`，实施时取下一个未占用版本，不改写旧迁移。

## 3. 布局与交互

```text
Data Agent
  新会话
  搜索会话

置顶
  每周经营数据复盘                 …
    经营分析
  常用 SQL 与指标核对              …
    未分组

项目                              +
  ▾ 经营分析                   +  …
      分析 9 月销售额变化         …
      华东区域毛利率对比          …
  ▾ 用户增长                   +  …
      新用户留存分析              …
  ▸ 临时研究                   +  …

未分组会话
  解释这段查询语句                …
```

- 延续暖灰底色、轻量选中背景和单行导航，侧栏宽度以 300px 为基准。长标题省略，悬浮提示完整标题，辅助技术可读取全名。
- 点击项目名只展开或折叠。项目区「+」创建项目，项目行「+」在项目内新建会话。全局「新会话」始终创建未分组会话。
- 会话「…」提供置顶/取消置顶、移动到项目、重命名；移动菜单列出所有活动项目及「未分组」。项目「…」提供重命名、删除。
- 项目重命名使用内联输入，Enter 保存、Esc 取消、失败保留草稿；遵守中文输入法组合态，不在候选确认时提交。会话改名沿用现有规则。
- 删除确认文案：「删除项目『项目名』？项目内会话将移至未分组，置顶状态保留。」不提供删除会话的选项。
- 菜单操作不触发会话打开，使用独立按钮而非按钮嵌套。键盘可访问全部动作，Esc 关闭后恢复触发按钮焦点，触屏保留明确入口。
- 真正为空、加载中和加载失败分别呈现。没有项目时保留创建入口，空项目保持可见。

## 4. 归属、展示和排序

1. 一个会话属于零个或一个项目。归属与置顶是独立属性。
2. 置顶会话只出现在置顶区，显示来源项目名或「未分组」；取消置顶回到原分组，不复制会话。
3. 移动已置顶会话保留置顶；删除项目时置顶会话继续置顶，来源改为未分组。会话 ID、消息、上下文和运行均不改变。
4. 置顶按置顶时间倒序、会话 ID 倒序排列。项目按创建时间正序、项目 ID 正序排列。新消息不改变项目顺序。
5. 项目内和未分组会话按现有更新时间倒序、会话 ID 倒序排列。组织操作会推进审计更新时间，接受其导致的组内排序变化。
6. 如显示项目数字，数字表示当前项目树中的未置顶会话数量；搜索时表示当前匹配数量。全部会话已置顶的项目显示「暂无未置顶会话」。
7. 搜索保留现有标题与 `tag` 的不区分大小写子串匹配，去除查询首尾空白。结果保留分区和项目路径，临时展开命中项目；清空搜索恢复之前的折叠状态。首版不增加项目名搜索。无命中时统一显示「没有找到会话」。
8. 新项目默认展开。移动当前会话时展开目标项目，保留搜索词；折叠项目不会关闭其中正在查看的会话。选中状态始终由会话 ID 决定。
9. 折叠状态保存在浏览器本地，按当前 API 基地址及项目 ID 区分；同一地址背后的代理目标切换不识别为不同实例。删除项目清理折叠记录；本地存储不可用时仅在本次页面记忆。

## 5. 数据结构

新增 `conversation_project`，复用 `TenantAuditedEntity`、`IdGenerator` 和既有审计填充。项目名去除首尾空白后为 1～60 个 UTF-16 代码单元，与 Java 字符串长度及前端 `maxLength` 保持一致。允许同名，关联使用 ID。

| 字段 | 类型与约束 | 语义 |
| --- | --- | --- |
| `id` | bigint identity，主键 | 仅内部定位 |
| `project_id` | varchar(64)，非空 | 现有 ID 生成器配合 `project` 前缀生成 |
| `tenant_id` | varchar(64)，非空 | 沿用固定租户 |
| `name` | varchar(60)，非空 | 项目名称 |
| `version` | bigint，非空，默认 0 | 重命名与删除的版本校验 |
| 通用审计及逻辑删除字段 | 与会话表一致 | 创建/更新时间、删除时间、删除标记 |

项目表建立 `(tenant_id, project_id)` 唯一约束和既有模式的逻辑删除一致性约束、租户外键。所有表、业务及通用字段均补中文数据库注释。

会话表新增两个可空字段：

| 字段 | 类型 | 语义 |
| --- | --- | --- |
| `project_id` | varchar(64) | 空表示未分组 |
| `pinned_at` | timestamptz | 空表示未置顶；非空表示最近一次从未置顶变为置顶的时间 |

增加 `(tenant_id, project_id)` 复合外键，引用项目对应唯一约束，不配置级联删除；增加活动会话上的 `(tenant_id, project_id)` 索引。外键只能保证项目行存在，逻辑删除项目的不可用性由事务内校验保证。

旧会话两个字段默认均为空，自然进入未分组。不复用 `tag`，保留其检索、分类和评测隔离语义。

## 6. 模块、对象与写入职责

- `agent-domain`：增加轻量项目模型；会话增加组织属性。项目名称业务约束放在领域工厂/行为中。
- `agent-persistence`：迁移、Entity、Mapper、ServiceImpl、转换和行锁。普通 CRUD 使用 MyBatis-Plus，不新增 XML SQL。
- `agent-web`：项目和组织应用服务、控制器、侧栏聚合查询、View 及契约测试。
- `agent-server`：仅装配及服务级验证；不承载业务门面。无需新增 Maven 模块。
- `frontend`：分区派生、项目行、操作菜单及侧栏状态管理。只提取与侧栏直接相关的逻辑。

Spring Bean 使用 `@RequiredArgsConstructor` 与 final 字段。Request、Response、View 优先 record；Entity 使用精确 Lombok 注解和受保护无参构造器。同构转换使用 Spring MapStruct，默认值由 View 的纯 `composeFromXxx(...)` 负责。

`ConversationSession`、Entity、摘要及详情 View 都包含 `projectId`、`pinnedAt`。读取和创建映射包含它们；现有 `ConversationPersistenceMapper.updateEntity(...)` 明确忽略这两个字段。只有专用组织操作写组织字段，普通标题/序号更新不回写旧归属。

组织操作使用持久化服务中的 Lambda Wrapper 显式设置可空字段，不依赖 Entity 默认忽略 null 的更新策略。否则移出项目和取消置顶可能写不进数据库。实际变更推进共享会话版本及审计更新时间，不更新消息/执行事件序号，不新增执行事件，不触发模型或上下文压缩。

## 7. 接口契约提案

| 接口 | 输入 | 成功响应 |
| --- | --- | --- |
| `GET /api/v1/agent-sidebar` | 无 | 200，`{projects, sessions}` |
| `POST /api/v1/agent-projects` | `name` | 201，项目 View 和 Location |
| `PATCH /api/v1/agent-projects/{projectId}` | `name, expectedVersion` | 200，项目 View |
| `DELETE /api/v1/agent-projects/{projectId}?expectedVersion=...` | 必传非负版本 | 204 |
| `PUT /api/v1/agent-sessions/{id}/organization` | `projectId, pinned, expectedVersion` | 200，轻量会话摘要 |

项目 View 包含 `projectId, name, version, createdAt, updatedAt`。聚合响应的 sessions 复用扩展后的 `ConversationSummaryView`；两数组必返，空使用 `[]`，组织字段为空时明确返回 null。聚合响应提供全部活动项目，包含空项目，不另增重复的项目列表 GET。

组织请求的三个键必须出现，`projectId` 允许 null，`pinned` 必须是布尔值，版本必须非负。禁止把缺失字段默认解释成 false 或 0；项目 ID 空字符串视为非法。

现有创建会话请求新增可选 `projectId`，省略或 null 创建未分组会话；现有会话列表和详情增加两个可空组织字段，原标题接口职责不变。

错误沿用现有全局边界：非法名称/缺失字段/非法 ID 或版本为 400；会话或活动项目不存在为 404；版本冲突为 409。不另设计错误协议。

先检查版本，再检查状态是否变化。版本正确且组织状态已与请求一致时返回当前摘要，不刷新置顶时间和版本；旧版本重复请求仍返回 409，不承诺命令重放。创建操作不自动重试网络失败；重复删除已不可见的项目返回 404。

## 8. 事务与并发

### 8.1 创建和组织变更

事务内先锁目标活动项目（有目标时），再锁会话并验证版本，最后执行局部更新。移出项目只锁会话；项目内新建也必须先锁项目再插入。源项目无需锁，不允许持有会话锁后补锁项目。行锁沿用持久化层已有 `FOR UPDATE` 封装。

运行中会话允许整理。消息提交、活动记录可能推进共享版本，使组织操作出现 409；前端刷新并保留用户选择供重试。首版接受这一限制，不增加独立组织版本。锁内不查询消息、不调用外部服务或模型。

### 8.2 删除项目

1. 锁定活动项目，验证项目版本。
2. 同一事务内用 Lambda Wrapper 批量清空仍属于该项目的活动会话 `project_id`，保留置顶时间，推进会话版本及更新时间。
3. 使用既有逻辑删除机制删除项目，保持删除时间与标记一致。任一步失败整体回滚。

删除持有项目锁期间，移入和项目内创建等待。删除先提交则它们返回 404；移入先提交则删除解除新关联。并发移出由会话行锁和版本校验协调，删除条件只更新仍属于被删项目的会话。

普通消息提交只锁会话及执行，不新增项目锁；项目操作不锁执行记录。禁止增加从会话锁反向获取项目锁的调用。逻辑删除会话没有恢复功能；未来新增恢复时必须重新检查其项目是否活动。

### 8.3 一致性读取

独立的 `ConversationSidebarQueryService` 在 Spring 代理生效的只读 REPEATABLE_READ 事务中读取项目和摘要，组装 `ConversationSidebarView`，防止一次响应拼接删除前的归属和删除后的项目列表。

复用现有批量会话摘要查询，不逐项目查询会话，不加载消息、时间线或产物。本期沿用现有全量列表规模，不新增分页；分组本身不会解决大量会话的查询成本。

## 9. 前端状态与同步

### 9.1 组件职责

- `ConversationSidebar`：搜索、新建入口、分区、项目空状态、错误提示。
- `ConversationList` / 提取的会话行：标题编辑、选中、状态及菜单。
- 项目行：折叠、新建、改名及删除。
- 侧栏状态 hook：聚合读取、操作编排、请求合并、计时器及折叠状态。分组由平铺摘要派生，不维护三份会话数组。
- `App.tsx`：保留路由、消息和执行编排，仅提取侧栏相关逻辑。

侧栏聚合结果是项目及组织元数据的权威来源；当前详情 SSE 继续负责消息和执行。摘要合并保留已加载的消息、执行及 Workflow 状态，不允许适配器的空默认值清空详情。迟到的详情响应或 `session_snapshot` 不得反写旧组织字段到侧栏。

### 9.2 刷新规则

首次加载、手动重试和组织操作结束后请求聚合接口。可见页面每 60 秒刷新，无论是否存在后台运行会话；替代现有有条件轮询，不叠加第二个计时器。隐藏页面停止周期刷新，重新可见/聚焦立即刷新，合并相邻触发。

不订阅或扩展摘要 SSE，不改变详情 SSE 数量及生命周期。健康网络下其他浏览器的变更在下一轮轮询或重新聚焦时收敛；不承诺跨端实时更新。

### 9.3 防止旧响应覆盖

侧栏 hook 使用递增请求代次与 AbortController，仅当前代次可应用响应。新刷新、客户端切换及组件卸载使旧请求失效；取消请求只是节省资源，正确性依赖代次校验。

组织写入开始时使已发侧栏读取失效并暂停周期刷新；结束后无论成功或失败均发起新的权威读取。首版同页组织写入串行，等待此次读取结束再恢复写入口；不禁用会话浏览、输入及运行。写入期间的新刷新触发合并为写入结束后的读取。

整体应用同一次聚合读取的项目和摘要元数据，不仅逐实体比较版本，从而正确处理删除。详情接口及详情 SSE 不负责恢复项目成员关系。会话内容正常按原有机制收敛。

### 9.4 失败与未知结果

- 初次读取失败显示重试；后续读取失败保留最后成功列表，不把失败解释为全部项目/会话删除。
- 不做乐观移位；写入及刷新均成功才提示整理完成。409 后刷新并保留目标选择，用户重试，不静默覆盖。
- 写入已成功但读取失败显示「更改已保存，侧栏刷新失败」，提供重试，不回滚服务端。
- 网络导致写入结果未知时显示「结果尚未确认」，先刷新再决定重试；不自动重新创建项目/会话。
- 初次读取成功前禁用组织入口。其他标签页删除项目造成 404 时刷新移除该项目，不切走当前会话。

## 10. 迁移与兼容

新迁移添加项目表、组织字段、约束、索引和中文注释；旧会话默认为未分组、不置顶。项目逻辑删除，不级联删除任何消息、执行或产物。

保留旧会话列表及标题/消息接口，创建请求未携带项目字段仍有效。更新 REST OpenAPI、示例和测试；会话详情新增字段时同步 `contracts/schemas/session-sse-event.schema.json` 中的快照结构，不改变摘要 SSE 协议。

前后端配套发布，数据库先迁移再启动新后端。旧前端继续调用原接口，但不能管理项目。所有运行和验收继续使用单实例、固定租户及身份。

## 11. 验收与验证

| 层次 | 必须验证的行为 |
| --- | --- |
| 持久化与 PostgreSQL 集成 | 历史会话默认值；null 清空成功；逻辑删除约束；删除回滚；移入/新建与删除并发；消息写入不恢复旧组织字段 |
| 应用与转换 | 名称边界；400/404/409；无变化请求；置顶与归属独立；解除归属推进版本；所有读取映射带齐字段 |
| 契约 | 项目操作、聚合与组织接口；明确 null；拒绝缺失字段；旧创建请求兼容；详情快照 Schema |
| 前端交互 | 每个会话只显示一次；来源名称；搜索标题和 tag；折叠恢复；新建位置；移动/取消置顶；键盘与输入法；删除文案 |
| 异步状态 | 旧读取/旧详情晚到；删除后旧数据晚到；写入中暂停刷新；保存后读取失败；未知结果；可见性和计时器清理 |
