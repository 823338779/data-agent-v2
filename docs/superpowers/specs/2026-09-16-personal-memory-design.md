# 跨会话个人长记忆设计规格

日期：2026-09-16；实施状态更新：2026-09-17。书面规格已确认，任务1–12功能已实现；真实PostgreSQL、双策略完整装配、重启恢复及前端测试/构建已验证。最终整体验证见实施报告，整体独立评审待完成；真实模型语义评测未执行，stub与语料结构测试不代表语义准确率。使用与验收流程见[个人长记忆使用与验收](../../个人长记忆使用与验收.md)。

## 已确认决策

| 决策 | 已确认内容 |
| --- | --- |
| 第一期范围 | 显式记忆、主 Agent 主动提炼、后台异步学习、管理页面/API、跨会话消费 |
| 可见范围 | 全局个人记忆，同一固定身份的全部项目、会话共享 |
| 自动学习 | 默认开启；同一个开关控制主 Agent 推断和后台学习 |
| 关闭学习后 | 停止自动写入，仍可显式记忆、手动管理和使用已有记忆 |
| 人工维护 | 用户可在对话中直接修改、删除人工记忆；目标含糊时先澄清 |
| 遗忘与恢复 | 删除并抑制自动恢复；用户可在对话或页面明确重新记住 |
| 架构 | 新增 agent-memory，全部持久化收敛在 agent-persistence，同时接入两种上下文策略 |

## 1. 目标与依据

结合 [长程记忆.md](../../长程记忆.md) 和 [长记忆【NOVA参考】.md](../../长记忆【NOVA参考】.md)，实现发现、写入、跨会话消费、人工维护和后台审查的完整闭环。前者区分 NOVA 现状与复刻建议，后者主要描述 NOVA 实现；本工程采用前者的并发、版本、证据和删除抑制建议，不复制参考实现中已知的缺口。

一条记忆保存一项能独立修订、删除的长期事实或偏好：

- `person_profile`：用户的稳定个人信息与偏好。
- `collaboration_preference`：有明确适用条件的长期协作偏好。

个人画像描述用户的稳定特点，例如职业、默认交流语言；协作偏好描述希望 Agent 如何分析、呈现与行动，例如“功能开发前先讨论设计”“排障时先列证据再推断”。NOVA 的历史分类名 `work_context` 在本工程统一改为 `collaboration_preference`；这是新增能力，不增加旧名称兼容接口。

一句话可以拆成多条独立事实，同一事实不重复归入两类。必须保留条件；“这次用英文”“好，继续”不推导为长期偏好。两类均是低可信历史信息，当前用户请求优先。

项目知识、业务指标、临时任务、工具输出和会话压缩摘要不进入个人记忆。即使用户要求记住业务信息，也说明个人记忆的边界，引导使用适合的项目文档等载体，不在本期增加例外路径，不虚构工程已有知识库能力。

身份遵循仓库规则：使用 `TenantContext`、`OperatorContext` 的固定身份，不设计认证或租户隔离。保留服务端身份字段用于来源与未来迁移，API 和工具不接受调用方自选身份。同一固定身份的全部会话、项目共享个人记忆，这不是项目级记忆。

## 2. 方案选择

| 方案 | 交付范围 | 取舍 |
| --- | --- | --- |
| 全部放入 agent-web | 完整能力集中在对话模块 | 接入直接，但记忆规则、后台审查和对话业务容易混合 |
| 独立 agent-memory，已选择 | 独立能力模块，复用现有数据库、工具及模型体系 | 边界清晰，持久化继续遵循现有模块约束 |
| 独立部署服务 | 远程记忆服务 | 增加调用及运维成本，当前没有必要 |

第一期交付完整闭环。小型个人记忆库采用关系数据库和已有快照比对，不引入向量检索。分阶段实施与验证，但这些阶段共同组成一次交付。

## 3. 已核实的工程接入点

- `ReactExecutionEngine` 通过 `ConversationContextRequestFactory` 和策略 resolver 构造模型输入。现有 LSM、hierarchical 两套策略必须同时支持个人记忆。
- `ConversationContextRequest` 当前仅包含固定 system 消息和工具定义，需补充独立的运行时上下文贡献，不能把个人记忆放入 `fixedSystemMessages`。
- `AgentTool.InvocationContext` 已有执行 ID、工具调用 ID 和稳定幂等键，可以复用。`ToolPolicyProperties` 的 initial、maximum 决定工具是否真正对模型可见，不能只注册 Bean。
- `ModelInvocationCoordinator.completeFinalAnswer` 在事务内持久化最终消息与 DONE 事件，适合作为完成轮次的审查边界。
- `AgentModelGateway` 是现有模型调用端口。后台使用隔离的调用循环，仅提供记忆工具，不执行主会话的其他工具、不发布主会话回答。
- 两套上下文策略当前使用各自的保守 token 估算器，并没有统一的 provider tokenizer。本期应适配现有估算规则，不宣称提供精确模型 token 计数，也不顺带重写整个预算系统。
- 已有 PostgreSQL、Flyway、MyBatis-Plus、Lombok、MapStruct、Micrometer 和 Testcontainers，可直接复用。

## 4. 模块职责

| 模块 | 本期职责 |
| --- | --- |
| `agent-domain` | 记忆类型、来源、快照、操作结果、任务状态等领域契约 |
| 新增 `agent-memory` | 内容规则、统一写入服务、记忆工具、注入文本构造、审查业务规则；依赖 domain、persistence、tool，不依赖 web |
| `agent-persistence` | 所有记忆 Entity、Mapper、ServiceImpl、MapStruct 转换、迁移、数据库锁及条件更新 |
| `agent-web` | 管理 REST、对话上下文接入、完成轮次标记、后台模型适配与执行编排 |
| `agent-context-common`、两套上下文策略 | 运行时记忆上下文的位置、预算与非持久化约束 |
| `agent-server` | 配置和运行时装配，不放记忆业务 HTTP 或业务处理 |
| `frontend` | 个人记忆管理入口、分类列表、增改删、配额与开关展示 |
| `agent-evals` | 可选真实模型语义评测，仅用于验证，不进入运行时依赖 |

`agent-memory` 需要获取对话证据或调用模型时声明窄接口，由 `agent-web` 适配；接口只传领域数据，不传 Mapper、供应商 SDK 或 HTTP 对象。运行时记忆贡献通过中立上下文契约传给两套策略，策略不直接读记忆数据库。

简单数据对象使用 record；Spring 依赖采用 Lombok 构造器注入；同构字段转换使用 MapStruct；View 默认值与场景差异通过自身静态工厂组装。普通 CRUD 和 CAS 使用 MyBatis-Plus Wrapper；只有 PostgreSQL 原子 upsert、任务竞争领取等数据库特性确有需要时写自定义 SQL，并注明原因。

## 5. 持久化与写入一致性

使用项目现有 ID、审计和时钟约定；迁移统一放入 `agent-persistence`，新建表和字段都有中文数据库注释。

主要记录：

- 个人记忆：分类、原文、规范化 hash、规范化版本、字符数、原始来源、人工保护标记、条目版本、创建/修改/确认时间。
- 记忆状态：固定身份、revision、settingsVersion、读取/显式写/自动学习设置、learningEpoch，同时作为统一写入互斥行。三个开关初始均开启；持久化设置优先于初始化默认值，重启不能重新开启用户已关闭的学习。
- 操作记录：稳定 request ID、请求摘要、结构化状态、目标 ID 和结果版本，和业务变更同事务提交；相同 ID 不同请求拒绝，不额外复制记忆正文。
- 证据关联：记忆与真实用户消息或管理操作事件的关联，保存会话和提示词版本；重复确认不丢失来源。
- 删除抑制：规范化版本、指纹、删除事件及 revision，不复制已删除正文；同身份的两类记忆统一检查指纹，不能通过换分类绕过遗忘。
- 审查任务：会话、learningEpoch、连续消息游标、待处理上界、领取时的处理上界、dirty/claimed generation、状态、到期时间、失败次数、owner、fencing token 和租约到期时间。
- 用户审查租约：单调递增 token、owner、到期时间；释放不删除 token 计数。

唯一约束分别是：状态/用户租约按身份唯一，操作按身份＋request ID 唯一，任务按身份＋会话唯一，抑制按身份＋规范化版本＋指纹唯一，证据关联按记忆＋证据类型＋证据 ID 去重。目标记忆、来源消息和版本均用持久化值核验，不能只校验引用格式。

内容、保护状态、确认时间或能力设置改变时增加整体 revision；记忆变更同时增加条目 version，设置变更同时增加 settingsVersion。只读、纯幂等重放和没有状态变化的自动重复不增加这些版本。learningEpoch 在关闭和重新开启时变化，不能复用旧 epoch。

全部写入经过统一事务边界：锁记忆状态行，校验幂等、后台资格、证据、保护标记、版本、删除抑制、重复和最终配额，再提交业务变化与结果。LLM 请求始终在数据库事务外执行。需要多个锁时统一采用状态行 → 后台任务 → 用户审查租约 → 目标记忆/操作记录的顺序；任务标记仅更新任务，不能持有任务锁后再反向获取状态锁。租约使用数据库时钟判断。

除目标条目的 expectedVersion 外，所有模型来源写入还要携带服务端在模型调用前冻结的 revision；不允许写入时无条件换成最新 revision。一次调用有多项操作时，只能依据自身成功提交的结果推进预期 revision；其他入口修改造成的冲突必须重读。幂等重放不重新执行副作用，结果明确区分历史操作成功与目标当前是否仍存在，不能因旧 CREATED 结果恢复已删除条目。

规范化版本 1 采用 `lowercase(Locale.ROOT)`、Unicode 空白折叠为空格、trim、移除尾部连续的 `. , ! ? ; : 。 ， ！ ？ ； ：`，再对 UTF-8 文本计算 SHA-256；原始正文保持不变。正文和规范化结果都必须非空。有效记忆使用身份、分类与规范化 hash 唯一约束兜底。精确重复先于配额判断。替换撞到其他条目时返回明确冲突，不偷偷覆盖或删除。规范化升级必须统一迁移，不能让各实例混用算法。

默认分类配额为 800/1500 个 UTF-16 单位，与参考资料口径一致；本工程只计正文之和，不计 NOVA 历史分隔符，API、提示词和数据库校验统一此口径。满额返回实际用量，不自动删除其他条目。

人工创建、编辑及明确确认均设置 `userProtected`，保留原始来源。用户显式重复 add 已有系统条目时，可以补证据并提升保护，不增加容量；纯自动重复 add 不刷新确认时间。自动推断和后台不能修改受保护条目。用户可以在对话中明确修改、删除人工记忆，无须强制页面确认。

主模型负责理解本轮自然语言意图。服务端绑定当前执行的真实用户消息，验证作者、消息角色、执行边界、目标和版本；只有 `write_reason` 而没有有效证据不能作为显式请求。历史指令、助手文本和工具输出不能冒充本轮用户授权。证据校验不能证明模型完全正确理解意图，误理解需要通过语义评测暴露，不用关键词规则冒充自然语言授权验证。

删除时物理移除正文及活动证据关联，保留最小操作元数据和抑制指纹；不能直接套用逻辑删除而仍保留正文。审计基类选择须与这一语义一致。删除不清除历史消息、既有工具过程记录或备份，本期不承诺对这些载体全面擦除。

## 6. 工具、API 与用户维护

`memory` 工具提供 `add/list/replace/remove`；后台另外开放 `confirm`，仅通过服务端私有执行模式启用。目标使用稳定 ID 和 expectedVersion，不提供快照序号删除或正文子串寻址。所有模型写入必须关联当前允许范围内的真实用户消息证据；会话和身份从服务端执行上下文解析。

主工具的新增、修改、删除都必须区分 `user_requested` 和 `agent_inferred`。显式请求可维护人工条目；自动推断只可维护系统条目并受学习开关控制。来源由可信执行模式及校验后的意图生成，取 USER_UI、USER_DIRECT、LLM_ACTIVE、BACKGROUND_REVIEW；后台不能自称人工来源。目标含糊先澄清，冲突后不能只换新版本号盲目重发。

返回结构化状态，包括 CREATED、ALREADY_EXISTS、UPDATED、REMOVED、CONFIRMED；拒绝原因区分 INVALID_REQUEST、UNSAFE_CONTENT、CONFLICT、DUPLICATE_CONFLICT、NOT_FOUND、PROTECTED、SUPPRESSED、QUOTA_EXCEEDED、LEARNING_DISABLED、LEASE_LOST、UNAVAILABLE。结果携带条目 ID/version、revision、created 和分类用量；模型只能依据真实成功状态宣称已保存。框架的工具执行状态和业务结果必须一致，不能把业务失败包在成功 observation 中而让后台误判。

| action | 主要参数与约束 |
| --- | --- |
| list | 可选 kind/cursor/limit；默认 20、上限 100；返回稳定 ID、version、来源、保护状态、快照 revision 和容量 |
| add | kind/content/用户证据；主模型需 write_reason；显式恢复另需 restore=true |
| replace | memory_id/expected_version/new_content/用户证据；主模型需 write_reason；不改变 kind |
| remove | memory_id/expected_version/用户证据；主模型需 write_reason；删除并抑制 |
| confirm | memory_id/expected_version/用户证据；只供后台确认未受保护条目 |

工具证据参数为真实用户消息 ID；实际会话、身份、允许证据范围、当前记忆快照和幂等键来自服务端。普通参数不能启用后台模式。初始工具可见性及最大允许集合中需纳入 memory，同时保留部署显式禁用工具的能力，不能只注册 Bean 而未进入真实模型请求。

主模型通过独立的运行时元数据获得当前可引用的用户消息 ID；后台输入直接携带证据 ID。元数据不改写用户原文，并计入输入预算；服务端重新验证，不能让模型猜测 ID。管理页面创建的操作使用已提交的人工操作 ID 作为事件证据，不需要虚构聊天消息。

管理 API 使用 `/api/user/memories`，写请求沿用仓库的 `Idempotency-Key` 请求头，不接收租户或用户 ID。列表提供分类用量、版本、来源和人工保护状态。错误响应复用现有服务异常封装及稳定业务错误码，不返回数据库异常或原始敏感输入。

| 方法与路径 | 契约 |
| --- | --- |
| GET /api/user/memories | 可选 kind/cursor/limit，按类别返回条目、用量及分页信息 |
| POST /api/user/memories | kind/content，可选显式 restore；人工创建并保护 |
| PUT /api/user/memories/{id} | content/expectedVersion；人工编辑并保护 |
| DELETE /api/user/memories/{id}?expectedVersion=... | 删除并抑制；不使用 DELETE 请求体 |
| GET /api/user/memories/settings | 返回三个开关及 settingsVersion |
| PUT /api/user/memories/settings | 提交修改的开关及 expectedVersion；未提供字段保持原值 |

参数/内容拒绝返回 400，不存在返回 404，版本/幂等/重复/删除抑制冲突返回 409，配额超额返回 422，依赖暂不可用返回 503。settings 的读取开关控制模型注入及工具 list，不阻止管理页面查看；显式写开关控制人工和显式工具写入；学习开关控制两条自动路径。页面首期只暴露已确认的自动学习开关，其他两项保留服务端/API 边界，三个开关初始均为 true。

前端从现有应用壳层打开个人记忆管理面板：分类展示、新增、编辑/删除、显式重新记住、配额提示和自动学习开关。展示正文、来源、人工保护状态及更新时间，空状态解释两类用途。页面明确关闭学习仍可使用已有记忆。版本冲突刷新数据但保留用户尚未提交的编辑内容，提示重新操作，不自动覆盖。设置提交失败时恢复界面真实状态；先被抑制、后明确恢复属于新 payload，必须使用新操作键。

对话内支持记住、查看、修改、忘记、重新记住；目标不清先澄清，不强制页面操作。容量/内容拒绝明确告知未保存及原因；容量错误提供用量与管理入口。已保存但本轮未注入不表述为保存失败，也不在每轮无关回答中打断用户。后台暂时失败走有界重试，不追加主会话错误回复。

## 7. 上下文消费与安全

每次模型上下文准备读取当前已提交的记忆，保证新会话及既有会话的新轮次均可使用。记忆贡献位于当前真实用户消息之前，使用 USER 角色、明确的运行时包裹和来源标识，不持久化成用户原话，也不写入会话摘要。

默认每类最多 20 条、总计 1024 个估算 token。分类内优先人工保护条目，再按确认时间倒序、稳定 ID 升序；合并候选后仍优先保护与近期确认，以 kind/ID 打破同序，并按分类标题呈现。不同于 NOVA 的最早创建优先，这可避免新修正的偏好长期排不到；读取本身不更新确认时间，不表示模型实际采用该记忆。

预算包含消费说明、标题、转义后正文与消息协议开销，按当前所选策略的现有估算规则计量。两种上下文策略均将该贡献计入软阈值和硬上限；优先保障当前用户请求、必要工具协议与固定规则，预算紧张时减少记忆，不能先完成预算判断再无条件追加。放不下的条目整条省略，包裹本身放不下则不注入，条数预筛选和 token 筛选的省略都计入统计。可选记忆不能导致本来无记忆可成功的必要输入因为追加而硬失败。

逻辑位置为固定 system → 历史及合法摘要 → 运行时记忆 USER 消息 → 当前真实用户消息及其后续工具协议。工具循环仍围绕同一用户轮次定位，不得插在 assistant tool call 和对应 tool result 之间；供应商合并相邻 USER 消息时保留来源包裹。注入贡献不作为压缩源，后台不从组装后模型输入提取新证据。

契约明确：只在相关时使用；当前请求与权威信息优先；不能把记忆当作业务指标来源或工具权限。内容校验拒绝常见密钥、角色伪装、运行时控制标记及危险控制字符；格式化时转义保留标记。文本扫描只能补充防御，不能证明任意自然语言无提示注入风险。

记忆读取失败跳过个人记忆并记录指标，主对话继续；写入失败明确返回失败。日志默认只记录 ID、状态、统计和耗时，不复制个人正文或用户证据。

## 8. 后台学习与删除边界

默认读取、显式写和自动学习均开启。自动学习同时允许主模型 `agent_inferred` 和后台审查；关闭后两条自动写入路径都停止，已有记忆的读取和显式管理由各自开关决定。提交前重新读取开关及版本，不能只在任务创建时检查。

完成轮次与审查标记需要持久化可靠衔接：在最终消息事务内写入任务标记，worker 只会读取提交后的任务。不使用单纯的提交后内存事件作为唯一投递来源，避免进程崩溃丢任务。不能吞掉标记失败却宣称任务已可靠投递；后台模型计算、失败及重试脱离主对话事务。数据库本身不可用时遵循现有主会话失败边界，不承诺绕过主数据库继续运行。

首次启用能力只审查之后成功完成的轮次，不默认回扫部署前全部历史。首次任务以触发轮次的用户消息为起点。关闭学习会更新 learningEpoch、revision 和设置版本，令在途旧 epoch 失效；重新开启从新 epoch 下完成的轮次开始，旧 epoch 待处理任务取消，不追溯关闭期间。取消不同于已审查，不得混用状态。新轮次的标记不能把尚未退出的旧 worker 伪装成新任务的合法 owner。

按会话 sequence 从游标开始正序分页；用户消息是新事实来源，最终 assistant 正文仅提供语境，工具过程、工具结果、注入上下文不参与学习。通过所属 execution 的持久化状态判断是否完成，不以正文非空判断。失败/取消轮次可记录为明确排除项；尚未终态化的消息不能跳过后推进游标。

默认每批最多 40 条完整正文、50000 个 UTF-16 单位，同时按包含提示词、快照、工具定义的后台完整输入预算缩小范围。单条消息仍无法完整容纳时进入 BLOCKED，原因 INPUT_TOO_LARGE，游标停在该消息之前；模型预算或限制改变后可重试。不得截断后伪报已完整处理；首期不增加超长消息分段归纳子系统。

后台模型获得两类已有快照与真实消息 ID，仅可调用记忆工具。单片段有成功的前台 add 仍继续审查其他事实。后台自然语言输出没有写入效力；模型正常无操作可以表示无新事实，模型异常不能当成无新事实。沿用当前 provider、模型选择和输出预算，不另设无法落实到 provider 的虚假输出上限；输入超过预算时缩小完整消息批次。后台循环有界：默认最多 8 次模型调用、16 次维护调用、120 秒总截止时间；后台执行器不无限占用主对话处理资源。

任务使用数据库竞争领取、用户级租约、心跳和 fencing，默认延迟 30 秒、启动扫描延迟 30 秒、扫描间隔 60 秒、每轮最多领取 4 个任务、租约 120 秒，心跳为 TTL/3。默认失败 5 分钟后重试，单批最多执行 3 次（含首次）后阻塞。新事件增加 generation 并延长目标上界；领取时冻结 claimedGeneration 和 claimedThroughSequence，完成只确认领取范围，执行期间的新事件保留待处理。任务标记不能重置正在运行的 owner/token。

任务状态为 PENDING、RUNNING、COMPLETED、FAILED、BLOCKED、CANCELLED。批次成功且尚有 generation 或未处理范围时回到 PENDING，全部覆盖后才 COMPLETED。租约过期可接管，旧 token 不能提交。新完成事件或影响阻塞原因的配置变化可重新激活 BLOCKED，但不能跳过未处理范围。没有模型配置时阻塞并保留游标。

每个操作使用由任务、epoch、证据批次、规范化动作摘要生成的稳定幂等标识，摘要包括动作、目标、预期版本和内容摘要；不使用重试随机 ID 或 provider 临时 toolCallId。一次输出的重复动作去重，已提交结果可供重试识别。

多项操作允许部分成功后失败；重试必须重读当前快照及已提交结果，不直接续跑旧计划，不假定整个模型循环原子。已提交相同请求不能重复执行；精确重复及删除抑制兜底，任意同义改写不承诺确定性幂等。

所有工具结果须分类处理：暂时故障、无效参数/证据、版本冲突和租约丢失不能推进未完成范围；安全、配额、保护或抑制拒绝可以记录为已判断但未保存。模型正常结束不等于所有操作成功。关闭学习则取消旧 epoch，不把取消当成学习完成。

用户删除在同一事务内增加 revision 和写抑制指纹；系统维护删除也保留抑制以免旧证据反复生成相同内容。在途旧 revision 不能提交，更晚的自动学习仍不能恢复被抑制的同指纹内容。用户可以通过管理页面或本轮对话明确重新记住；对话恢复必须有删除之后的新用户消息、有效 revision 和 restore=true。旧证据或旧请求重放不能撤销抑制。

恢复、配额检查、新建同事务执行，失败不能提前移除抑制；恢复使用新条目 ID，旧请求不得寻址新条目。仅保证精确规范化指纹和旧快照不复活，不承诺识别所有同义改写，也不承诺撤回已经发往模型的请求。

超过 30 天未确认只成为审查候选，不自动 TTL 删除。后台只有新证据明确否定或修订时才维护系统条目；不按最后读取时间淘汰记忆。删除会话不等于删除独立个人记忆。

## 9. 验收标准

### 9.1 验证范围

1. 持久化和统一写入：先测试规范化、配额、幂等、保护、版本与删除抑制；真实 PostgreSQL 多连接验证重复写入和配额竞争。
2. 工具和管理 API：验证工具在 initial/maximum 中真正可见；工具执行结果与数据库一致；校验证据和参数；API 契约验证冲突及错误状态。
3. 两种上下文策略：验证新会话读取、删除后不再注入、USER 角色、当前位置、无历史污染、估算预算及输入硬限额。
4. 后台审查：验证正序连续游标、超过 40 条不漏审、新事件 generation、重启接管、旧 token 拒绝、关闭学习、部分成功重试、人工修改与删除竞争。
5. 管理页面：验证增改删、版本冲突、配额展示、开关行为和操作后刷新。
6. 联调与文档：更新中文使用说明及默认参数，执行与改动模块匹配的 Maven 测试、前端测试和构建，再进行整体装配回归。

自动化模型 stub 验证链路与确定性规则；真实模型评测另行报告稳定偏好、临时指令、弱肯定、冲突修订等案例，不能用提示词关键词断言代替语义准确率证据。若 Docker、模型或数据库不可用，应明确报告未执行的验证范围。

### 9.2 行为验收矩阵

| 编号 | 场景 | 必须满足的结果 |
| --- | --- | --- |
| M01 | 工具显式保存后服务重启，同身份切换项目或新会话 | 记忆仍在，能跨项目和会话消费；只说已记住而没有成功结果不算通过 |
| M02 | 初次部署、关闭学习后重启及在途自动写入 | 初始开启；用户关闭状态持久化；主 Agent 推断和后台均停止写入，显式路径与读取仍可用 |
| M03 | 同内容大小写、空白、尾标点差异；库存满 | 返回已有条目，不重复占容量，原文保持；纯重复不因满额失败 |
| M04 | 多连接并发写相同内容及争抢剩余容量 | 不重复、不超额；不使用单 JVM 锁模拟数据库并发保证 |
| M05 | 替换为其他条目已有文本、旧版本提交、同幂等键不同参数 | 明确冲突，原数据不变 |
| M06 | 系统条目被人工编辑或明确确认 | 原始来源保留、人工保护生效；自动路径不能覆盖，本轮明确用户请求可修改或删除 |
| M07 | 伪造证据 ID、助手/工具证据、引用旧指令作本轮显式授权 | 服务端拒绝；模型不能用普通参数开启后台模式或指定身份 |
| M08 | 删除与在途任务竞争、换分类自动写回 | 旧 revision/token 不得写回，相同抑制指纹跨分类生效；活动正文及证据已移除 |
| M09 | 页面或对话明确重新记住；旧请求重放 | 新用户依据可恢复且获得新 ID；旧请求不能恢复；恢复失败仍保留抑制 |
| M10 | 页面增改删、配额拒绝、版本冲突、开关保存失败 | 展示实际状态；冲突保留未提交编辑；设置失败不显示虚假成功 |
| M11 | LSM、hierarchical 注入及紧预算工具循环 | USER 来源包裹保留，位于当前用户消息前；工具协议配对完整；估算不超硬限，必要时舍弃记忆 |
| M12 | 多轮注入、摘要压缩、后台再学习 | 读取不刷新确认时间；注入不写入原文或摘要源，不当作新用户证据 |
| M13 | 超过 40 条增量，前台已记住 A 而片段还有 B | 正序分批不漏审；只去重 A，仍判断 B；超大单条明确阻塞且不跳过游标 |
| M14 | 执行期间新事件、进程重启、租约接管 | 新 generation 保留，持久化进度可恢复，旧 token 不能提交 |
| M15 | 后台多项操作部分成功后失败 | 重试重读快照与结果；不重复已提交相同动作，未完成批次不提前推进 |
| M16 | 安全/配额拒绝，模型/数据库故障，缺少模型配置 | 区分已判断未保存与未成功处理；后者保留游标并有界重试或阻塞 |
| M17 | 关闭后重新开启自动学习 | 旧 epoch 失效，关闭期间和旧 epoch 未完成任务不回扫；取消不标记为已审查 |
| M18 | 角色标记、运行时包裹、常见密钥、不可接受控制字符 | 拒绝或安全转义，不制造新的高权限消息；错误和日志不回显敏感正文 |
| M19 | 注入读取故障、保存故障、本轮预算不足 | 分别是无记忆降级、明确未保存、已保存未注入，三者不混淆 |
| M20 | 原会话、Git、工具注册及两种上下文策略回归 | 既有业务契约保持；父 POM 可构建；运行时不依赖 agent-evals |

语义评测另覆盖“一句话两个事实”“当前任务要求不能泛化”“条件性偏好不能丢条件”“同义重复”“冲突修订”“模糊删除”“明确恢复”。报告模型及提示词版本、保存正确性、过度记忆、漏记和误修改案例；代码级测试不能证明自然语言意图识别完全正确。

实施阶段已执行修改模块及依赖的Maven测试、前端测试/构建与服务装配回归；迁移、竞争和重启使用真实PostgreSQL/Testcontainers。各轮实际执行/跳过数量分别记录在实施报告，不累计重复suite作为独立用例总量。真实模型语义评测未执行；既有需显式启用的外部服务测试跳过不计为通过。

## 10. 本期范围限制

本期不增加向量数据库、项目级记忆、项目知识库、认证系统、语义主题级永久遗忘、自动满额整理、自动批量语义归并、超长消息分段归纳、NOVA 专用澄清能力、全量导出或独立审计管理平台。这些不影响个人记忆基础闭环，避免将参考资料中的可选扩展全部变成首期功能。

## 11. 故障与可观测性

复用现有 Micrometer 记录各来源新增/重复/拒绝量、配额、注入候选数和实际条数、估算 token、审查队列延迟、失败重试、版本冲突、租约丢失、删除抑制命中。指标不使用正文或用户 ID 作为高基数标签；日志仅记录关联 ID、状态、错误码及耗时，不默认记录个人正文、证据或完整模型输入。

后台调度与模型执行使用有界资源，不无限挤占主对话；后台模型失败不向已完成主会话追加错误回答。工具写入和开关保存失败必须有明确结果。无个人记忆可降级继续主对话；主数据库故障仍按现有执行失败边界处理。
