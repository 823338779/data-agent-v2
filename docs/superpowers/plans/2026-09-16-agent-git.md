# Agent Git 仓库维护实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用户通过卡片确认 Agent 的文件变更，服务端将同一份内容提交并推送到共享指标仓库 main。

**Architecture:** 本地 agent-git 承载 Git CLI、会话工作区、冻结快照和提交服务。现有 ReAct/Tool SPI 不变，agent-web 提供确认接口和卡片关联，前端增加一种受控卡片。Git push 成功即结束。

**Tech Stack:** Java 21、Spring Boot 4.1、MyBatis-Plus、Lombok、Git CLI、React 19、Vitest。

**Spec:** `docs/superpowers/specs/2026-09-16-agent-git-design.md`

## Global Constraints

- 首版使用本地 `agent-git` Maven 模块，不引入 MCP。
- 所有会话共用一个远端仓库，目标分支为 `main`。
- 所有拟提交的文件变更必须经过卡片按钮确认。
- Agent 的责任终点是确认提交已成功推送；不查询、不等待指标平台生效。
- 不重构 ReAct 循环、`AgentTool` SPI、会话执行状态机、上下文压缩或数据分析 Workflow。
- 不迁移现有 UI Block 类型或 artifact 查询职责。
- Entity、Mapper、ServiceImpl 和迁移只放在 agent-persistence。
- 仅单实例，固定租户和身份；不增加认证或多租户功能。
- 不执行仓库脚本；不暴露任意 Shell、Git 参数、目录或远端地址给模型。
- 中文类、字段和关键并发/恢复注释；精确 Lombok、record、现有基类和 Wrapper 优先。
- 每项先写行为测试，观察失败，再实现和验证；提交仅包含该项文件。

## 文件与接口分工

1. Task 1：agent-git 模块及纯本机 Git/文件基础。对外类型放在 `com.datagent.agentv2.git` 下的 `config`、`model`、`local` 包。
2. Task 2：persistence 的 Git 表及状态服务；agent-git 的应用服务与恢复，不注册 Tool 或 HTTP。
3. Task 3：Tool、Skill、HTTP、消息卡片、POM/配置和接口契约。
4. Task 4：前端卡片、真实仓库集成验证、部署说明与全范围验证。

各任务可新增职责单一的内部辅助类型，但不改变这里确定的上层职责。记录接口实际签名供下一任务使用；签名微调必须同步本计划，不能让消费者猜测。
