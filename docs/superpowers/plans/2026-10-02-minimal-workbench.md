# 简洁版 Agent 工作台实施计划

目标：将用户已选择的简洁版静态图落地为可用的对话、Git 审阅和记忆体验。

执行方式：当前会话连续实施。按用户“确认静态画面，再实现页面”的顺序推进，不重新选择视觉方向。工作区为现有 develop 分支，保留用户文档变更；不自动提交或推送。

规格：`docs/frontend-workbench-redesign.md` 的“当前方案”与页面交互章节。此次首版不新增能力说明接口，不承诺未配置能力。Git 文件摘要不展示现有接口没有提供的增删行统计。

技术：沿用 React、TypeScript、现有 REST/SSE 客户端、Lucide、React Markdown、Vitest；不安装新依赖。

- [x] 提取 MessageComposer，供首页与会话复用；首页先创建会话再发送，失败保留输入，不重复创建。
- [x] 草稿按会话在内存中保存，运行中不排队；保留中文输入法与换行行为。
- [x] 为首页发送失败、切换草稿、运行中防重复提交添加行为测试，先失败再实现。

- [x] 核对桌面、平板和窄屏布局、Git 代码差异与键盘可达性；样式包含长内容溢出约束和减少动态效果规则。集中修复后确认一次。
- [x] 检查最终差异与注释。不改 Java，不运行与本次变更无关的 Maven 构建；真实后端未启动时明确联调限制。

## 重点风险

- 首页创建成功但消息失败时，重试必须使用已创建会话。
- 提交期间切换会话不能清掉另一会话的草稿。
- 流式文字不能打断用户正在阅读的历史。
- 隐藏 Git 审阅区不得自动触发确认，也不能重置候选版本或轮询期限。
- 原有侧栏并发保护、SSE 单连接与记忆独立生命周期保持通过。
