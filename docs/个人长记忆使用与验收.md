# 个人长记忆使用与验收

## 功能与边界

个人记忆随固定身份跨项目、跨会话共享。`person_profile` 保存稳定个人信息（职业、默认语言）；`collaboration_preference` 保存带适用条件的长期协作偏好（如“排查生产事故时先列证据，再分析原因”）。一句话可拆成独立事实；临时指令、弱肯定、业务指标、项目知识、工具结果和压缩摘要不应保存。历史记忆是低可信辅助信息，当前请求优先。

当前阶段无认证与租户隔离，使用固定租户和身份，不允许 API/工具自选身份。首次部署三个开关默认开启，持久化设置优先，重启不会覆盖关闭状态。

| 设置 | 控制边界 | 关闭后仍可做什么 |
| --- | --- | --- |
| readEnabled | 模型注入与对话 memory list | 管理 API/页面仍能查看库存 |
| explicitWriteEnabled | 页面/API 人工增改删及明确对话写入 | settings 接口仍可重新开启；自动学习由独立开关控制 |
| autoLearningEnabled | 主 Agent 推断与后台审查 | 显式管理和已有记忆使用分别遵守另外两个开关 |

页面只暴露自动学习开关。关闭、重新开启学习均切换 epoch；旧 epoch 在途结果失效，关闭期间及旧 epoch 未完成历史不补扫。第一次部署也不回扫旧历史。消息证据时间来自数据库；迁移前没有可信数据库时间的消息不能作为新记忆/恢复证据，聊天显示时间保持原样。

应用 `application-business.yml` 默认选择 hierarchical，支持个人记忆与后台纯估算；lsm 同样支持。显式部署 raw 可以启动，但缺少纯估算器时后台任务 BLOCKED，不调用模型。工具 `memory` 同时在 initial/maximum 默认集合；部署可显式移除它。

## 使用方式

从应用壳层打开“个人记忆”面板，按两类查看、添加、编辑、删除或明确重新记住。对话可说“请记住……”“查看我的记忆”“把那条改为……”“忘记……”“重新记住……”。含糊删除应先澄清目标。人工条目自动保护，但本轮明确对话仍可修改或删除；自动路径不得覆盖。模型只有收到成功工具结果才能声称已保存。

版本冲突后刷新数据并保留未提交编辑；不要仅换版本盲目重试。相同操作键及相同参数可重放，相同键不同参数返回 CONFLICT。明确恢复是新动作，必须使用新键、新用户证据和 `restore=true`，恢复生成新 ID。删除物理移除活动正文与证据并留下规范化指纹；跨分类相同指纹也不能自动写回。此保证不覆盖任意同义改写，也不撤回已发往模型的输入。删除会话不删除独立个人记忆；删除记忆不清除聊天历史、既有工具过程、备份，不能据此宣称全面擦除。

容量按 Java UTF-16 正文单位计算（表情可能占两单位），不是字节数：分类用量 `Σ content.length()`；替换后用量 `原用量－旧正文.length()＋新正文.length()`。先判重复再判配额，满额精确重复仍可复用，不自动淘汰。规范化包括小写、空白折叠、尾部标点移除，不等于语义去重。读取不会刷新确认时间，超过30天未确认也不会自动删除。

部署下调分类容量后，实际用量可能暂时超过当前上限。管理列表与设置仍可用，用户可以逐条删除，直到回到限额内；新增、替换仍校验最终用量，不会自动提高上限或淘汰存量。

网络故障或503后应使用原操作键重试，因为提交结果可能未知。重放成功响应中的 `targetExists=false` 表示操作曾成功、目标现已删除；页面保留新增正文或修改草稿，只有用户明确点击重新记住才发起新操作，不会因历史成功自动恢复条目。变更后的权威刷新会使旧分页响应失效，迟到页不会覆盖新的库存和用量。

每次模型准备读取已提交记忆，按人工保护、近期确认和稳定ID排序。默认每类候选最多20条、整体记忆贡献1024估算token；实际服从可信部署配置与模型完整输入硬限。估算包括包裹和协议，不宣称供应商精确token。条目整条省略，不能只注入空包裹；已保存但预算不足未注入不等于保存失败。读取故障跳过记忆，写入故障明确返回未保存；主数据库故障仍受既有会话失败边界约束。

## 默认部署参数

下表属性统一位于 `data-agent.memory`，可用 Spring Boot 外部配置覆盖。

| 属性 | 默认值 | 含义 |
| --- | --- | --- |
| person-profile-limit | 800 | 个人画像 UTF-16 正文容量 |
| collaboration-preference-limit | 1500 | 协作偏好 UTF-16 正文容量 |
| injection-per-kind-limit | 20 | 每类注入候选上限 |
| injection-token-budget | 1024 | 记忆贡献估算token预算 |
| review-message-limit | 40 | 每批完整消息上限 |
| review-char-limit | 50000 | 每批 UTF-16 正文上限 |
| max-model-calls | 8 | 每批模型调用次数 |
| max-maintenance-calls | 16 | 每批维护调用次数 |
| review-deadline | 120s | 模型循环总截止时间 |
| review-delay | 30s | 完成事件后的延迟 |
| scan-initial-delay | 30s | ApplicationReady 后首扫延迟 |
| scan-interval | 60s | 后续扫描间隔 |
| claim-batch-size | 4 | 每轮最多领取数 |
| lease-duration | 120s | 数据库租约 TTL；心跳 TTL/3 |
| retry-delay | 5m | 暂时故障重试间隔 |
| max-attempts | 3 | 含首次的批次尝试次数 |

后台使用4个固定执行线程、零等待队列、2个心跳/截止守卫、1个扫描线程。同一固定用户只有1个有效审查租约，并不允许同用户并行提交4个任务。模型调用不持数据库事务。双token、revision、epoch与数据库时钟共同约束提交。

后台只读取完成轮次的真实用户消息与最终助手语境，连续游标不跳过未完成消息。单条完整消息超出字符或完整输入预算时 BLOCKED/INPUT_TOO_LARGE，游标停在该消息前；不截断、不分段伪报完成。失败保持游标，最多3次后BLOCKED；取消与审查成功不同。新完成事件或相关配置变化可激活阻塞。配置摘要包含实际provider/model、预算、策略、限制和提示词版本；Ollama实际有效ConnectionDetails地址变化也参与。相同配置重启不重置阻塞；旧null指纹需新事件。首次升级摘要范围扩大可能触发一次重试。

关闭学习时若不能以完整claim确认旧用户租约，等待剩余TTL，不能只按相同owner释放新任务租约；新后台任务可能短暂等待，前台记忆读写不受此等待限制。

## API 与最小请求

所有写请求带 `Idempotency-Key`。列表 `kind/cursor/limit` 可选，limit默认20、上限100；按分类返回entries/nextCursor，完整分类配额不随分页减少。条目版本从1开始，设置版本从0开始。

| 请求 | 内容 |
| --- | --- |
| GET /api/user/memories | 分类库存、完整用量与revision |
| POST /api/user/memories | kind/content，可选restore |
| PUT /api/user/memories/{id} | content/expectedVersion |
| DELETE /api/user/memories/{id}?expectedVersion=1 | 无请求体 |
| GET /api/user/memories/settings | 三个开关及settingsVersion |
| PUT /api/user/memories/settings | expectedVersion及要修改的开关；未给字段保持原值 |

以下仅使用虚构测试内容和本机隔离部署；替换响应中的真实ID/version再编辑或删除。

```sh
curl -X POST http://127.0.0.1:8080/api/user/memories \
  -H 'Content-Type: application/json' -H 'Idempotency-Key: demo-add-1' \
  -d '{"kind":"person_profile","content":"默认使用中文"}'
curl 'http://127.0.0.1:8080/api/user/memories?kind=person_profile&limit=20'
curl -X DELETE 'http://127.0.0.1:8080/api/user/memories/REPLACE_ID?expectedVersion=1' \
  -H 'Idempotency-Key: demo-delete-1'
```

```powershell
$base = 'http://127.0.0.1:8080/api/user/memories'
$settings = Invoke-RestMethod "$base/settings"
$payload = @{ expectedVersion=$settings.settingsVersion; autoLearningEnabled=$false } | ConvertTo-Json
Invoke-RestMethod "$base/settings" -Method Put -ContentType 'application/json' `
  -Headers @{ 'Idempotency-Key'=[guid]::NewGuid().ToString() } -Body $payload
# 重新启用前重新 GET settings，使用新版本、新操作键。
```

成功状态：CREATED、ALREADY_EXISTS、UPDATED、REMOVED、CONFIRMED。拒绝码如下；传输错误使用统一ProblemDetail，带requestId，不返回正文/SQL。

| HTTP | 稳定码 |
| --- | --- |
| 400 | INVALID_REQUEST、UNSAFE_CONTENT；HTTP数字/形状校验为VALIDATION_FAILED |
| 404 | NOT_FOUND |
| 409 | CONFLICT、DUPLICATE_CONFLICT、PROTECTED、SUPPRESSED、LEARNING_DISABLED、LEASE_LOST |
| 422 | QUOTA_EXCEEDED |
| 503 | UNAVAILABLE |

工具的框架失败状态与业务拒绝一致。HTTP删除成功为204，其余成功按接口返回200/201。

## 指标及隐私

指标标签仅有限枚举 `source/status/kind`，无用户/会话/记忆ID、正文或证据。`memory.operations` 在首次操作事务提交后记录来源及业务结果；回滚与纯幂等重放不算新提交。`memory.quota.used/limit` 表示最近读取/提交的分类库存观测。

`memory.injection.candidates/entries/tokens` 在每次最终prepare记录一次；tokens来自实际选中贡献，不从候选正文推算。`memory.read.failures` 来自真实读取降级边界。`memory.queue.wait` 从任务availableAt（到期可领取时刻）计到成功领取，不包括配置延迟。`memory.review` 记录实际提交的PENDING/COMPLETED/CANCELLED/FAILED/BLOCKED与耗时；无效fence单列LEASE_LOST，未能提交的依赖异常为UNAVAILABLE。第三次暂时失败计BLOCKED，守卫与worker finally不能重复计数。终态短事务与指标发布使用同一监视器；数据库收敛若阻塞，守卫可能短暂等待，模型及历史读取不持该锁，数据库更新处仍按真实时钟双fence拒绝过期提交。

memory专属过程日志只保留关联ID、有限状态/错误码及时间统计，不默认复制输入、输出、证据、错误正文或预览；数据库工具过程与前端展示契约仍按原功能保留。

## 真实模型语义评测流程

语料位于 `backend/agent-evals/src/test/resources/memory-eval/cases.jsonl`。结构测试只核对10条材料完整性，不调用模型；服务集成使用stub，不能据此宣称自然语言语义准确。

1. 在专用测试部署清空测试数据库（含记忆、抑制、操作与会话），迁移并初始化。绝不连接业务数据库。每个案例独立清理，避免跨案例污染；不要只删活动条目留下抑制。
2. 按initialState准备前态。active通过管理API创建并记录真实ID/version；deleted先创建后DELETE产生真实抑制。语料alias仅是标注名，不能冒充ID。需要自动来源前态时在隔离环境按真实对话路径生成并核对来源。
3. 按messages顺序发送实际对话，等待execution终态，记录memory工具框架状态、业务状态及实际保存内容/分类/保护状态。删除恢复的最新消息必须在删除之后发送。语义重复记录是否复用既有ID、是否新增/修改，不能只看条数。
4. 新建会话执行相关探针，记录跨会话行为；保留条件，确认临时英文/弱肯定没有泛化。区分显式主路径和后台路径，记录后台任务终态与游标。评估后台时等待真实调度结束，不以回答完成冒充学习完成。
5. 人工逐条标注“正确保存、过度记忆、漏记、误修改”；模糊遗忘需先澄清；明确恢复需新ID。未标注、执行失败、未执行分别列出，不混进语义准确率分母。保留失败个案说明，模型话术本身不等于持久化成功。

建议执行顺序：temporary-language → conditional-evidence → stable-role → language-profile → two-facts → weak-praise → semantic-duplicate → explicit-correction → ambiguous-forget → explicit-restore；每条仍独立重置并准备前态。
