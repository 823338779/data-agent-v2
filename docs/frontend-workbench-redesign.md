日期：2026-10-02。状态：用户已确认“采用简洁版”，前端实现与本地验证完成，真实后端联调待进行。

## 已确认的目标

面向开发者，通过对话完成任务，查看执行过程、Git 变更和个人记忆。用户选择先看静态效果图，确认画面后再实现。

成功标准是任务流程更顺畅、状态更清晰、结果更易读，并且现有真实业务能力均有适当入口。效果图中的任务、文件差异与执行记录均为演示数据。

## 当前方案：收敛简洁的对话工作台

用户明确反馈“都不太好看，要求画面风格收敛简洁”。首轮三套方案不再作为候选，以下方案取代原视觉方向。

- 主色仅使用黑白灰，颜色只用于必要的差异与状态语义。
- 窄侧栏提供新对话、搜索、置顶、项目、最近会话与个人记忆。
- 默认只有一个对话主区；任务标题放在顶部小标题中，不重复制作大标题。
- 回答直接排版在阅读区，取消头像、外层卡片、装饰图标和无业务意义的徽章。
- 执行过程只保留一行折叠入口，需要时展开。
- Git 候选先呈现一行文件摘要，点击查看差异后才打开审阅区。确认动作留在完整审阅状态中。
- 输入框使用细边框、简短提示和一个发送按钮，不显示未支持的附件、提及或模型切换入口。
- 默认对话、审阅展开、记忆管理和移动端均沿同一视觉规则实现。

## 已放弃的首轮方案（保留设计决策背景）

### A：运行控制台

深石墨底色、薄分隔线、低饱和薄荷绿操作色。左侧会话与项目、中间对话及执行摘要、右侧变更审阅。适合频繁关注任务运行状态的开发者。风险是长篇阅读和小屏空间更紧张，需要严格控制次要信息密度。

### B：代码审阅工作台

近白色阅读区、浅灰导航、深绿色主操作。打开 Git 变更时扩大右侧差异区，关闭后恢复宽阔对话。适合对话与代码审阅交替进行的日常工作。风险是视觉表达较熟悉，品质主要取决于排版、状态反馈和切换细节。

### C：任务手册

暖白底色、墨色文字、青绿色章节导航。每个任务按任务、结果、变更组织，执行记录作为可展开证据。适合长任务阅读与复盘。风险是章节导航必须随真实内容出现，不能把尚未完成的任务装成完整报告。

三套图使用相同的演示任务“完善本地启动说明”。用户认为不够简洁，已全部放弃，不实现这三套主题。

## 页面与交互范围

### 首页与导航

- 桌面默认展示会话导航；窄屏收为抽屉，键盘和关闭按钮均可操作。
- 首页直接提供任务输入、真实最近会话以及能力相关引导，避免先进入空会话才能输入的多余步骤。
- 首页输入提交时，先创建会话再提交消息。创建成功、发送失败时保留该会话与输入，重试不得重复创建。
- 搜索继续基于现有会话摘要，不宣称支持消息全文搜索。
- 项目、置顶、改名与移动继续复用当前侧栏逻辑。

### 对话与输入

- 回答使用适合长文的行宽、标题层级、表格横向滚动和代码排版。
- 用户仍位于底部时跟随新内容；主动向上阅读后停止跟随，显示“回到最新”。
- 草稿按会话保留；首版可限定为当前浏览器页面生命周期，避免未经讨论持久保存敏感输入。
- Enter 发送，Shift+Enter 换行；中文输入法组合期间不触发发送。
- 运行中保留输入草稿并提供取消入口；不引入未实现的排队语义。
- 复制回答和代码提供短暂完成反馈与失败反馈。

### 运行反馈

- 执行状态、流连接状态、Git 候选状态独立展示。
- 使用服务端阶段与过程记录描述当前进展；不显示推测的百分比或虚构步骤。
- 默认只显示过程摘要与当前工具；点击后查看安全载荷、耗时与错误。保留截断提示。
- 断线时说明连接正在恢复或需要重试，保留已有正文；恢复先读取权威详情，不重新提交任务。
- 失败、取消保留部分结果并清楚标记。重新执行是新的提交，不能把恢复连接当作重新执行。
- 同一会话仅保留当前必要的详情 SSE，侧栏摘要继续遵循现有生命周期。

### Git 审阅

- 消息中保留候选摘要和“查看变更”入口；完整文件差异在审阅区展示。
- 审阅区显示文件列表、完整差异、目标分支、基线与候选状态。
- 主操作明确标注“确认并推送”；提示目标分支，不能让用户误以为只保存草稿。
- 继续由服务端状态、版本与确认规则决定允许的动作，不根据文字推测状态。
- 保留重复点击防护、旧请求失效、网络超时后查询实际状态、有限轮询及人工核实。
- 需要重新确认时展示最新候选；失效、失败、待核实分别提供相应动作。
- 不新增跨会话 Git 任务列表，因为当前没有对应的查询能力。

### 个人记忆

- 独立面板，不替换会话路由，不取消正在执行的任务。
- 继续区分个人画像和协作偏好，显示来源、内容及允许的操作。
- 保留学习开关、分页、编辑版本冲突和删除确认语义。
- 关闭返回原焦点；窄屏使用全屏面板，滚动与焦点不穿透到背景。

## 动效与适配

- 导航、面板和过程展开使用短暂、可打断的过渡；不为每段流式文本重复播放入场动画。
- 执行中使用小范围状态动画，终态停止；不让整屏持续闪烁。
- 尊重 prefers-reduced-motion，禁用非必要动画。
- 桌面以右侧模态面板承载完整审阅；平板优先保证对话宽度；手机以单主区域加抽屉或全屏审阅呈现。
- 核对 1440px、1024px 与 390px；按钮焦点、菜单键盘操作、长标题、长代码、空列表和失败状态均在验收范围。

## 后端最小补充建议

本次先复用现有接口，不新增能力说明接口。首页采用通用任务输入，不展示无法核实的 Git 或联网可用性。后续确需展示时，可新增 agent-web 下的只读能力说明接口，只报告现有服务配置能确定的能力，不把“已配置”等同于外部服务健康。

不得返回密钥、连接字符串、仓库本地绝对路径或其他内部配置。无需新增数据库表；沿用构造器注入和 record，读取现有配置能力，避免重复注册工具或改变 Skill 激活机制。

除此以外，已发现的主要缺口均可以先在前端解决。暂不增加附件、模型切换、任务队列、认证或新工作流。
